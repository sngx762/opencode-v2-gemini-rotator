The Problem: Gemini API 429 Rate Limits in OpenCode

When using Google Gemini models (such as google/gemini-2.5-flash or google/gemini-2.5-pro) in OpenCode V2, developers frequently encounter 429 Too Many Requests or 503 Service Unavailable errors due to per-minute rate limits and free-tier quota caps.

When this happens during an AI agent workflow, generation halts, requiring manual key swapping or waiting for reset periods.

The Solution: Native OpenCode V2 Key Rotation

opencode-v2-gemini-rotator is a lightweight server plugin that intercepts requests to generativelanguage.googleapis.com. Upon detecting rate limits, temporary quota errors, or invalid keys, it automatically puts the rate-limited key on cooldown, picks the next active key from your configured pool, and triggers OpenCode's native retry pipeline.

  • No monkey-patching: Built cleanly using OpenCode V2's Plugin.define and ctx.session.hook APIs.
  • Single-file install: No npm install or compilation needed. Just copy index.ts into ~/.config/opencode/plugins/gemini-rotator/.
  • Smart cooldowns: Respects Google's RetryInfo and Retry-After headers.
  • Domain security: Only modifies requests targeting official Google Gemini endpoints.

Quick Installation

# Create plugin folder in OpenCode V2 global config
mkdir -p ~/.config/opencode/plugins/gemini-rotator

# Copy index.ts and LICENSE into plugin directory
cp index.ts LICENSE ~/.config/opencode/plugins/gemini-rotator/

# Set your pool of Gemini API keys
export GEMINI_API_KEYS='KEY_1,KEY_2,KEY_3,KEY_4'
export GOOGLE_GENERATIVE_AI_API_KEY='KEY_1'

# Test with OpenCode V2
opencode run --standalone --model google/gemini-2.5-flash "Hello world"
