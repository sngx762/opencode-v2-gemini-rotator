Scenario 1: Large Multi-File Code Refactoring

Before: When asking OpenCode to refactor an entire module across 15+ files using google/gemini-2.5-flash, high token generation triggers Google's per-minute rate limit on step 4. OpenCode throws HTTP 429 Resource Exhausted and terminates the prompt session midway.

After with Rotator V2: Upon receiving the 429 response on key #1, the plugin flags key #1 on a 60-second cooldown, immediately assigns key #2, and notifies OpenCode's retry engine. The multi-file refactoring completes seamlessly without user intervention.

Scenario 2: Background Automated Test Generation

Before: Running automated batch test suite generation in background mode (e.g., opencode service or opencode run --standalone) fails silently if Google API endpoints experience brief 503 Service Overloaded spikes.

After with Rotator V2: The plugin detects 503 errors, applies a brief 10-second pause on the current key, switches to an alternate key, and allows the test suite generation process to complete cleanly.

Scenario 3: Multi-Key Key Pool Management

Before: Developers manually edit environment variables or config files every time a Gemini key runs out of quota.

After with Rotator V2: Developers set export GEMINI_API_KEYS='KEY_1,KEY_2,KEY_3,KEY_4,KEY_5,KEY_6' once. The plugin manages active status, cooldown tracking, and key availability dynamically in memory.
