1. Key Pool & Request Interception

When an HTTP request is made by OpenCode V2 towards https://generativelanguage.googleapis.com, the http.request hook registered via ctx.session.hook intercepts it:

  1. Parses GEMINI_API_KEYS (or options.keys) into a candidate pool (up to 256 keys).
  2. Identifies the first key that is not currently on cooldown or marked invalid.
  3. Injects the chosen key into the x-goog-api-key header while stripping inline ?key= query parameters to prevent query key exposure in logs.

2. Response Classification & Error Handling

The http.response hook monitors response headers and JSON error payloads:

HTTP Status Error Subtype Plugin Cooldown Action
429 Resource Exhausted / Rate Limit Parses Retry-After or RetryInfo (Default 60s). Rotates key.
503 Service Overloaded Parses delay header (Default 10s). Rotates key.
400 / 403 Quota Exceeded Temporarily pauses key for 10s. Rotates key.
400 / 403 API_KEY_INVALID Permanently marks key invalid until process restart. Rotates key.

3. Native OpenCode V2 Retry Pipeline

Unlike V1 plugins that patched globalThis.fetch and ran internal infinite retry loops, V2 delegates retries to OpenCode's native retry engine via Effect.ts. OpenCode V2 enforces an overall budget (up to 10 retries), preventing runaway background loops while seamlessly resolving transient API throttles.
